# Settings

Every Timelake feature has a setting that turns it on or off or chooses how it behaves. Settings are declared once,
in the engine, and can be set at up to four levels. When a setting is set at more than one level, the most specific
one wins:

- **Create:** fixed when the table is created, by its options (`--time-column`, `--series-key`, `--chunk`,
  `--no-dedup`, `--no-ingest-time` on the CLI; `time_column=`, `series_key=`, `chunk=`, `dedup=`, `ingest_time=` in
  Python).
- **Table:** a table property under the `timelake.` prefix, stored with the table and used by every reader and writer.
  Set it at creation (`--prop`, `properties=`) or later (`timelake alter`, `Table.set_properties`). Other engines
  ignore these properties.
- **Session:** for one SQL session, overriding the table's value: `SET timelake.read_dedup = false` in SQL,
  `--set read_dedup=false` on the CLI, `Lake(..., settings={...})` in Python (any spelling: `read-dedup`,
  `timelake.read_dedup`). `SHOW timelake.read_dedup`
  shows the session's value.
- **Call:** for one append or maintenance run, through its options (`AppendOptions`, `MaintainOptions`, or the
  method's keyword arguments in Python).

A setting has one name. Table properties spell it with dashes (`timelake.read-dedup`); SQL needs identifiers, so it
uses underscores (`timelake.read_dedup`). Both spellings, and the bare name, name the same setting. An unknown name, a
bad value, or a setting set at a level it doesn't allow is an error. The table below gives the bare names;
`format-version` is set by Timelake itself (at creation and by `timelake upgrade`). Tables written by a newer Timelake may carry
settings this one doesn't know; reading ignores them. Storage options, which say how to reach the bucket and which
requests to use, are given when a lake is opened; they are on the [Storage](/docs/storage) page.

```shell
timelake settings                    # every setting: default, levels, description
timelake settings iot.readings       # the table's values; defaults in parentheses
timelake alter iot.readings --set read-dedup=false --set retention=90d
timelake alter iot.readings --unset retention    # back to the default
```

```python
table.set_properties({"read_dedup": "false", "retention": None})
lake = timelake.Lake("s3://bucket/lake", settings={"read_dedup": "false"})
```

Durations are a number and a unit: `s`, `m` (minutes), `h`, `d`, `w` or `y`, or the long forms (`90 days`, `2 weeks`). Examples: `30m`, `36h`, `90d`, `1y`.

## Filter pushdown

With `filter-pushdown` on, a scan decodes the filter columns of a row group, evaluates the filters, and decodes the
other columns only for the rows that pass. On local disk (TSBS, standard scale, repeat queries) it cut the geomean by
4–5% and selective group-bys by 15–40%, and made queries that keep most rows up to 20% slower. On object storage it
costs a request round trip per row group: with 20 ms per request, first queries took 12–17% longer, while repeat
queries served from the block cache were 5–8% faster. So `auto` turns it on
for local files and off on object storage. Timelake's scans ignore DataFusion's own
`datafusion.execution.parquet.pushdown_filters`; scans that remove duplicates use pushdown either way.

## Iceberg properties set at creation

- `write.format.default = parquet` and `write.parquet.compression-codec = zstd`. Timelake writes data files with the codec this names, at `write.parquet.compression-level` where the codec has levels (ZSTD 3 by default). Table creation and `timelake alter` reject an unknown codec, or a level the codec doesn't have such as `high` or a negative one for `gzip`; set by another engine, such a value fails writes, never reads. Codecs: `zstd`, `lz4`, `snappy`, `gzip`, `brotli`, or `uncompressed` (from JavaScript: `zstd` and `snappy`). Set it with `timelake alter tsbs.readings --set write.parquet.compression-codec=lz4`. On TSBS IoT, repeat queries on local disk took 11.5 ms with ZSTD 3, 11.1 ms with ZSTD 1, 12.3 ms with LZ4 and 10.8 ms with Snappy, while the data took 200, 204, 242 and 277 MB: reading doesn't wait on decompression, and on object storage bytes cost time and money, so ZSTD 3 stays the default.
- `write.metadata.previous-versions-max = 20`: keeps `metadata.json`, which every query reads, small. Older metadata files are deleted by snapshot expiry.

## Schema

Arrow types are mapped to the closest lossless Iceberg type when a table is created:

- 8- and 16-bit integers become `int`; `UInt32` becomes `long`; `UInt64` is rejected.
- Timestamps of any unit are stored in microseconds; time-zone-aware timestamps become `timestamptz` (UTC).
- Dictionary-encoded columns use their value type; large and view string and binary types become string and binary.
- The time column is NOT NULL, and a text time column is stored as a UTC timestamp.

Schema evolution isn’t supported yet: the schema is fixed when the table is created.
